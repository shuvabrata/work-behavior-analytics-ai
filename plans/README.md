## Notes

- **⚠️ The realm template is NOT the realm.** `--import-realm` is create-only, so editing `deploy/keycloak/realm-wba.json.template` changes nothing on a running stack, silently. After any template change, run `./scripts/keycloak-realm-reconcile.sh` and verify against the **running realm**. See `ADMIN_GUIDE.md` → "Applying a realm change". Plan 063 addresses this structurally.
- **045 is resolved and its file is gone.** The finding — the read-only validator rejecting entity ids that merely *contain* a write keyword — was fixed by `c6c608d6` (#347, "Implement value-aware read-only check for Cypher queries"), which added `src/app/api/graph/v1/cypher_read_only.py` (a lexer-driven token check replacing the text-wide regex scan) plus `tests/test_cypher_read_only.py` and `tests/test_cypher_read_only_values.py`, and **deleted the plan file in the same commit**. The row has been removed from "Open plans" and the plan recorded below. Two stale doc references to `plans/047-cypher-read-only-value-aware-check.md` remain in `src/app/api/graph/v1/cypher_read_only.py:15` and `tests/test_cypher_read_only.py:8`; they are cosmetic (a plan number that would be reused if a new 047 were ever written) and were left as-is rather than edited under `reconcile`.
- **005**: finding still present and re-verified on `8395a9e5` — unguarded `worker.join()` at `src/app/ai_agent/mcp_integration/client_manager.py:54`.
- **057 producer-scan item 5 is failing for an environment reason, not a code reason.** The running stack's producers and consumer log `Failed to fetch service token ... ConnectionError` and then `sending daemon request unauthenticated`, and the producer cannot reach `api:8000` at all (`Errno 111 Connection refused`). Their `git` history and `docker compose ps` agree they were started before the compose network came up. **The producers are one-shot services** (`docker compose run --rm github-producer`), so item 5 must be re-run after a rebuild, not judged from the current container logs. Do not read these logs as a 055/057 defect. The provider `wba-ai-github-producer` also spends its time retrying RabbitMQ (`AMQPConnectionError`), which is consistent with the same timing window.
