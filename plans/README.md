## Findings considered and rejected

- **Chat history not rendering after navigation, as a regression to bisect.** Fixed by `dadc7013` and was not a regression from any single commit: every revision of the chat page across all branches lacks a callback that renders `chat-messages` from `session-store` without a user action. The page never had a mount-render path, so there was no commit to revert. Recorded here so nobody re-bisects it.
- **Server-side chat history endpoint.** `GET /api/v1/chats/{id}` returns only `exists` and `message_count`; adding a message-history endpoint would let history survive a hard reload, which is a real capability but not this bug — the client already holds the conversation. Deferred as a product decision, not a defect.
- **A global spacing retune, applied app-wide.** Densifying the shared `SPACING_*` tokens was rejected in favour of plan 010's per-page `.dense-page` scope. `SPACING_MEDIUM` (24px) is the Analytics cards' padding and `SPACING_SMALL` (16px) appears 96 times across every page, so a global change would tighten the card and form pages that already have appropriate breathing room. Plan 010 leaves every `SPACING_*` value untouched for exactly this reason.
- **A user-selectable density mode (comfortable / compact).** Feasible but rejected for now: ~112 literal px values in the stylesheet bypass the token layer, so a toggle would be half-broken until those are routed through custom properties, and it doubles the visual-verification surface (16 routes × 2 modes). Deferred rather than dropped; plan 010 leaves the values centralised enough to make it a later option.
