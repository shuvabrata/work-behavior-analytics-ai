  **Import policy — the repo convention this change established.** Every
  `common.auth` import added by 055 is **module-level**. The plan initially
  specified a lazy import in `src/common/runtime_settings/client.py`; the
  operator reversed that: *"Unless there is a circular dependency, the code must
  assume files are present to import and import statements must be global. I
  don't want ModuleNotFoundError [handled]. Let it fail if import fails."*
  There is no cycle (`common.auth` imports only `requests`, `os`, `threading`,
  `time`, `dataclasses`, `common.logger`). The consequences, worth remembering:

  - **`Dockerfile.ui` is an allow-list, not a whole-tree copy** — it ships only
    `src/common/{__init__.py,logger.py,runtime_settings/,auth/}`. Any future
    `src/common/` module that lands in the UI's import closure needs its own
    `COPY` line, or the container dies at import. Verified exception: the UI has
    no `KEYCLOAK_*` env and no `.env` mount, so `get_service_token()` there can
    only raise `ServiceTokenError` and degrade — shipping the module grants no
    credential. When 056 routes the UI snapshot fetch through `api_client`, this
    `COPY` can be dropped again.
  - **Import failure ≠ token failure.** `ModuleNotFoundError` propagates (broken
    deployment, operator must see it); `ServiceTokenError` degrades to an
    unauthenticated request (Keycloak outage must not stop a scan). The call-site
    `try`/`except ServiceTokenError` blocks are the second, not a workaround for
    the first — do not widen them to catch `ImportError`.

  **Two operator-gated items remain; neither blocks 056:**
  1. **The live token checks were not run.** `src/common/auth/` reaches a running
     producer container only after its image is rebuilt (there is no source
     bind-mount for the four connector services), and the realm must be re-imported
     for the `oidc-audience-mapper` to land on `wba-internal` (the recipe is in
     `ADMIN_GUIDE.md`, "To re-seed from the variable instead" — it drops only the
     derived `keycloak` database). After both, run the two `docker compose exec -T
     github-producer` blocks in the plan; they must print a positive token length,
     `reused True`, and decode to `aud=["wba-internal"]`, `azp=wba-internal`, roles
     including `wba-service`. **If `wba-service` is absent, 053's realm template is
     at fault — do not widen another role.**
  2. **`KEYCLOAK_SERVICE_CLIENT_ID` is not set in `.env`.** The helper falls back to
     its `wba-internal` default, so this is harmless today, but an operator who
     changes the client id in Keycloak without adding the variable gets a
     `ServiceTokenError` whose message says the *secret* is unset. The plan's
     compose defaults (`${KEYCLOAK_SERVICE_CLIENT_ID:-wba-internal}`) cover the
     containers; the .env omission is worth a follow-up.
