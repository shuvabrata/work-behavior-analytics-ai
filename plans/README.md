## Findings considered and rejected

- **Parameterise `common/auth/service_token.py` for the admin client.** Rejected:
  it is connector-runtime code that reads `os.environ`; the API has a settings
  object and a separate secret, so a local cache in `app/auth/keycloak_admin.py`
  is cheaper and touches nothing the connector images ship.
- **Move existing admin routes under `/api/v1/admin/`.** Rejected for this plan:
  pure churn across every UI call site, no functional gain; `AUTHZ_MATRIX`
  already declares the grant level per route.
- **Role filtering in the user list.** Rejected: Keycloak's `/users` endpoint
  cannot filter by role; doing it correctly needs a different endpoint and a
  design of its own.
- **Integration tests that create/update/delete real Keycloak users.** Rejected:
  the operator verifies those by hand (Step 14); the unit suite covers the
  guards against stubs.
